# Harper Android Grammar Assistant

## Project Purpose
Harper Android is an on-device, accessibility-based grammar assistant. It provides system-wide text corrections by observing user input across the OS using Android's `AccessibilityService`, analyzing the text locally using the Rust-based [Harper](https://github.com/elijah-potter/harper) engine, and rendering lightweight suggestion overlays for quick corrections.

## Architecture Summary
The application is composed of two primary boundaries:
1. **Kotlin / JVM (Frontend)**: Responsible for the Android `AccessibilityService`, UI overlay injection via `WindowManager`, view text extraction, tracking input debounce states, and ensuring security policies.
2. **Rust (Backend)**: Houses the `harper-core` engine compiled to Android native targets. Exposes a native API bridge generated by `UniFFI`.
See [`docs/architecture.md`](docs/architecture.md) for deeper details.

## Prerequisites
- **Java**: JDK 17 (or compatible version configured in Android Studio)
- **Android SDK**: Must include Platform 36 and Build-Tools
- **Android NDK**: Required for JNI linking
- **Rust**: The Rust toolchain (`rustup`)
- **cargo-ndk**: Cargo plugin for compiling Android targets

## Local Setup
To verify your environment is ready to build Harper, run the environment check scripts:
- **Windows**: `.\scripts\check-environment.ps1`
- **macOS / Linux**: `./scripts/check-environment.sh`

These scripts will ensure that your Android SDK, NDK, and Rust targets are properly linked and installed.

## Build Commands
```bash
# Compile and build the Debug APK (Automatically triggers the Rust/NDK build process)
cd android
./gradlew assembleDebug

# Compile the Release APK (Includes R8 Minification and AOT Baseline Profiles)
./gradlew assembleRelease
```

## Test Commands
```bash
# Run Android JUnit and Robolectric Tests
cd android
./gradlew testDebugUnitTest

# Run Rust Core Engine Tests (via FFI models)
cd rust/harper-android
cargo test
```

## Emulator / Device Workflow
1. Start an Android 14+ Emulator or connect a physical device.
2. Run `.\gradlew installDebug` to install the app.
3. Open Android System Settings -> Accessibility -> Downloaded Apps -> Harper Android.
4. Enable the service. The service will prompt for consent to read screen contents.
5. Open any supported text field (e.g., Google Messages or the internal Fixture App) and begin typing to see the overlay suggestions.

## GitHub Actions Workflow
The project runs standard CI/CD through GitHub Actions (if configured in `.github/workflows`). Standard workflows run:
- Rust formatting (`cargo fmt`) and lints (`cargo clippy`).
- Kotlin static analysis and linting (`./gradlew lintVitalRelease`).
- Execution of all unit tests and instrumented UI tests.

## Project Structure
- `android/`: The primary Android Studio project folder containing Kotlin source code, resources, and Gradle build definitions.
- `rust/`: The Cargo workspace housing the `harper-android` UniFFI bindings and linking logic to `harper-core`.
- `docs/`: Technical specifications regarding architecture, privacy, accessibility, and development workflows.
- `scripts/`: Development and CI utilities (e.g., environment checkers).
