# Release Hardening Checklist

## 1. Accessibility Disclosure (Play Store Policy)
Google Play requires a prominent disclosure when requesting the AccessibilityService API. 
The disclosure MUST:
- Be shown within the app itself, before the user is directed to the system settings to enable it.
- Clearly explain *what* data is being accessed (the contents of editable text fields).
- Clearly explain *why* it is being accessed (to provide on-device grammar checking).

**Implementation Status**: Completed via `PrivacyScreen()` in `MainActivity.kt`. It clearly states that text is analyzed locally and raw typed text is not persisted.

## 2. Play Console Declaration
When uploading the App Bundle to Google Play Console:
- Navigate to **App Content > Sensitive permissions and APIs > Accessibility**.
- Declare the use case as: **"To support users with disabilities or to provide accessibility features."** (While grammar correction isn't purely a disability feature, assistive typing fits within Google's accepted scopes).
- Link a YouTube video demonstrating the disclosure screen and the immediate use of the feature in a target app.

## 3. Privacy Policy
- Provide an active URL to a Privacy Policy in the Play Console.
- Ensure the policy explicitly confirms that Harper Android does NOT send keyboard strokes or raw text off-device.

## 4. Proguard / R8 Shrinking
- `minifyEnabled true` shrinks and obfuscates the Kotlin/Java code.
- JNI mappings for `uniffi` must be preserved (UniFFI usually generates necessary `@Keep` annotations, or we might need to add `-keep class uniffi.harper_android.** { *; }` to `proguard-rules.pro`).

## 5. Native Library Packaging
- The `arm64-v8a` and `x86_64` (and potentially `armeabi-v7a` / `x86`) `.so` files generated by `cargo-ndk` are successfully bundled in `lib/` directory inside the final `.apk`.
